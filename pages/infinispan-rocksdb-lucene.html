Integrating Infinispan with RocksDB and Lucene: A Complete Guide

In this comprehensive guide, we'll explore how to integrate Infinispan with RocksDB for persistent storage and Lucene for powerful indexing capabilities. This combination provides a robust caching solution with excellent performance characteristics and search capabilities.

1. Understanding the Components

The integration consists of three main components:

  • Infinispan: A distributed in-memory data grid platform
    • Description: Infinispan is a distributed in-memory data grid and cache designed for high-performance, scalable data storage. It provides features such as data replication, partitioning, and transactional capabilities.
    • Key Features:
      • Supports distributed, embedded, and standalone modes
      • High availability with data replication and failover
      • Supports persistence with JDBC, RocksDB, and other backends
      • Offers APIs for Java, REST, Hot Rod, and Memcached
      • Integration with Kubernetes for cloud-native deployments
      • Strong consistency guarantees with transactional support
    • Use Cases:
      • Caching layer for high-speed access to frequently used data
      • Session storage for web applications
      • Distributed event processing and streaming
  • RocksDB: A high-performance embedded database for key-value data
    • Description: RocksDB is a high-performance, embedded key-value store optimized for fast read and write operations, particularly on SSDs. It is based on LevelDB but enhances performance through advanced optimizations.
    • Key Features:
      • Log-structured merge (LSM) tree-based storage engine
      • Efficient use of storage with compression techniques
      • Supports transactions and snapshot isolation
      • Optimized for low-latency, high-throughput workloads
      • Configurable tuning for different performance requirements
    • Use Cases:
      • Embedded storage for applications requiring fast persistence
      • Storage engine for databases like MyRocks (MySQL)
      • Key-value storage for real-time analytics and logging systems
  • Lucene: A powerful full-text search engine library
    • Description: Apache Lucene is a high-performance, full-text search library that provides powerful indexing and querying capabilities. It is the backbone of search engines like Elasticsearch and Solr.
    • Key Features:
      • Advanced full-text search with tokenization and stemming
      • Efficient inverted index for fast lookups
      • Ranked search results using TF-IDF and BM25 algorithms
      • Support for phrase queries, wildcards, and fuzzy searches
      • Scalable and optimized for large-scale indexing
    • Use Cases:
      • Powering search engines for websites and applications
      • Indexing and searching log files in large systems
      • Implementing recommendation and discovery features

2. Implementing Custom RocksDB Store

First, let's look at implementing a custom store for Infinispan that uses RocksDB as the backing store:

@Store
@SuppressWarnings("unchecked")
@ConfiguredBy(RocksDbStoreConfigurationV2.class)
public class RocksDbStoreV2<K, V> implements AdvancedLoadWriteStore<K, V> {

    @Override
    public void start() {}

    @Override
    public void stop() {}

    @Override
    public boolean delete(Object key) {}

    @Override
    public void write(MarshalledEntry me) {}

    @Override
    public MarshalledEntry load(Object key) {}

    @Override
    public void writeBatch(Iterable<MarshalledEntry<? extends K, ? extends V>> marshalledEntries) {}

    @Override
    public void deleteBatch(Iterable<Object> keys) {}
}

This implementation provides the core methods needed for storing and retrieving data from RocksDB.

3. Configuring RocksDB Store

The RocksDB store configuration is handled through a dedicated configuration class:

@ConfigurationFor(RocksDbStoreV2.class)
@BuiltBy(RocksDbStoreConfigurationBuilderV2.class)
@SerializedWith(RocksDbStoreConfigurationSerializerV2.class)
public class RocksDbStoreConfigurationV2 extends AbstractStoreConfiguration {
    final static AttributeDefinition<CompressionType> COMPRESSION_TYPE =
        AttributeDefinition.builder("compression-type", CompressionType.NONE)
            .immutable()
            .autoPersist(false)
            .build();

    final static AttributeDefinition<Integer> BLOCK_SIZE =
        AttributeDefinition.builder("block-size", 0)
            .immutable()
            .build();
}

5. Lucene Integration

The Lucene integration is configured with specific indexing properties:

indexingBuilder
    .addProperty("lucene_version", "LUCENE_CURRENT")
    .addProperty("default.indexBase", DeploymentPath.getIndexDir(false) + File.separator + name)
    .addProperty("default.directory_provider", FSExtDirectoryProvider.class.getName())
    .addProperty("default.indexmanager", NRTExtIndexManager.class.getName())
    .addProperty("default.indexwriter.index_flush_interval", String.valueOf(baseConfig.getInt("index.flush.interval")))
    .addProperty("default.indexwriter.ram_buffer_size",
        String.valueOf(Math.max(1, configValue.getLong("storage.indexBufferSize") / (1024 * 1024))))
    .addProperty("default.worker.execution", "sync")
    .addProperty("default.reader.strategy", "shared");

Key Lucene Configuration Properties

  • default.indexwriter.index_flush_interval: Controls how often the index changes are flushed to disk. Lower values provide better durability but might impact performance.
  • default.indexwriter.ram_buffer_size: Determines the amount of RAM that may be used for buffering added documents before they are written to disk. Here it's calculated from the storage.indexBufferSize configuration (default 16MB).
  • default.worker.execution: Set to "sync" for synchronous execution of indexing operations, ensuring immediate consistency but potentially impacting performance.

6. Memory and Transaction Configuration

The final step involves configuring memory management and transaction settings:

Configuration template = indexingBuilder
    .memory()
    .storageType(StorageType.BINARY)
    .evictionType(EvictionType.valueOf(configValue.getString("eviction.type")))
    .evictionStrategy(EvictionStrategy.REMOVE)
    .size(configValue.getLong("eviction.size"))
    .locking()
    .isolationLevel(IsolationLevel.REPEATABLE_READ)
    .transaction()
    .lockingMode(LockingMode.OPTIMISTIC)
    .transactionMode(TransactionMode.TRANSACTIONAL)
    .build();

    # Create Cache
    cacheMgr.defineConfiguration(name, template);
    cache = cacheMgr.getCache(name);

Conclusion

This integration provides a powerful combination of Infinispan's caching capabilities, RocksDB's storage efficiency, and Lucene's search capabilities. The configuration options allow for fine-tuned performance and reliability based on specific use cases and requirements.

For production deployments, it's recommended to:

  • Carefully tune the Lucene indexing parameters based on your workload
  • Monitor RocksDB performance metrics
  • Adjust cache eviction settings based on memory availability
  • Implement proper backup strategies for both cache and index data
